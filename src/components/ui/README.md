# components/ui

Presentational primitives with no knowledge of the portfolio's content. Two
naming conventions live here deliberately:

| Shape | Meaning | Example |
| --- | --- | --- |
| `lowercase.tsx` at this level | Generated by the shadcn CLI. Safe to restyle, but expect `npx shadcn add` to overwrite. | `button.tsx`, `card.tsx`, `tabs.tsx` |
| `PascalCase/` folder | Authored by hand. The CLI never touches these. | `Navigation/`, `Icon/`, `Toast/` |

`components.json` points shadcn's `ui` alias at this directory, so a generated
file always lands as `ui/<name>.tsx`. **Do not hand-write a `PascalCase/` folder
that shadows a generated primitive** — that is how the repo previously ended up
with both `ui/card.tsx` (shadcn) and `ui/Card/card.tsx` (an unrelated persona
card), and both `ui/button.tsx` and a leftover Storybook `ui/Button/Button.tsx`.
If you need a variant of a generated primitive, extend it in place or wrap it
under a clearly different name.

There is intentionally **no barrel file** here. Primitives are imported by
path (`@/components/ui/button`) so that a page pulls in only what it renders;
a barrel would re-export the whole design system into every route chunk and
undo the code splitting in `src/App.tsx`.

Feature-level and layout components do have barrels — see
`src/features/*/index.ts` and `src/components/layout/index.ts`.
